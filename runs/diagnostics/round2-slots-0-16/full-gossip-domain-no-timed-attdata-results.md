# Full-gossip timed-attestation-data omission control

## Result

This predeclared native-MVS pair omits only the timed
`GetAttestationData(slot=1, committee=0)` request from the coherent full-gossip
writer composition. Both arms remained fast. The omission arm completed all 48
DomainData probes with a 7.492 ms maximum; the enabled reference completed all
48 with a 10.542 ms maximum. Neither skipped a scheduled probe or produced a
deadline error.

This pair does not discriminate whether the timed request contributed to the
earlier run's large checkpoint-count cohort. The fast enabled reference shows
that one real timed request did not trigger the earlier 6.856-second pause in
this enabled run, so the request does not invariably trigger it. The fast
omission arm does not show that the request was unnecessary for that earlier
pause; that conclusion would require a seconds-scale positive in an omission
arm. No repetition was run to seek one.

## Matched construction

Both fresh arms use `GOMAXPROCS=4`, native shared-MVS iteration, 120,000 valid
validators, 15,000 valid slot-one publications over the prescribed two-second
source schedule, six real GossipSub validation pipelines, production
batch-verifier limit 1,000, and 48 DomainData probes on the absolute slot-one
250 ms grid. Both retain:

- all prerequisite forks at epoch zero and a Heze state/domain;
- the real locked fork-choice `FullHead` selection and coherent public
  `CanonicalNodeAtSlot(1)` result;
- a successful actual `GetAttestationData` preflight against a separate
  temporary cold cache;
- a newly constructed measured cache and full real core service;
- the real cold `HeadSyncCommitteeIndices(validator=0, slot=1)` prerequisite;
- probe zero in the same child goroutine and start-barrier structure; and
- the same absolute slot-two deadline for all 48 DomainData probes.

The omission flag gates the measured attestation-data goroutine, RPC stream,
handler observation/drain, response, head-state copy, and measured-cache fill.
It does not gate the preflight or any chain and workload preparation. The
omission arm emits an explicit client record with `omitted=true`, an omission
reason, and zero invocation/return timestamps. The parent asserts no measured
handler admission, server record, or head-copy record, and asserts that the
measured cache remains cold. The RPC's launcher and observer allocations are
also necessarily absent, so this is a whole-request toggle rather than a
head-copy or lock-only toggle.

The two fresh fixtures use the same construction, validators, workload shape,
and count, but their wall-clock genesis fields make the signed messages and
roots nonidentical. The omission arm used genesis
`2026-09-06T19:56:53Z` and root
`b3c7eb0c8ff60277fe3fe78c55c9eaef7fff2998a71290e108d292fb153442b4`.
The enabled reference used genesis `2026-09-06T19:58:12Z` and root
`6b8e0ce3be950e7bb3034e5a052060b3f7f2865187221a77fd76f56f6d82dc37`.

## Interpretation and limits

The result rejects a deterministic version of the natural-writer hypothesis:
one early, cold, real `GetAttestationData` request is not sufficient on every
otherwise coherent run to produce a seconds-scale DomainData pause. It does
not refute a timing-sensitive interaction involving that request and the rest
of the full workload. The observed cohort size, publication timing, and RPC
timing varied between the earlier positive and this pair even though the
prescribed construction stayed fixed; these untraced arms do not identify
which internal scheduler, garbage-collection, or finalizer conditions differed.

The earlier untraced native positive remains a valid observation: 6.856 seconds
with 1,324 peak iterators, compared with 3.298 ms in its stable-snapshot arm.
The separate trace repetition directly observed Count work preempting on all
four Ps while gRPC reader and writer goroutines remained runnable. This new
pair adds a matched null for the whole timed attestation-data request; it does
not replace either result or transfer their cohort sizes into these runs.

As documented in
[`full-gossip-domain-writer-results.md`](full-gossip-domain-writer-results.md),
the fixture is one BN plus one lightweight publisher, uses a different
committee selection and round configuration from retained E1/H, and observes
only the validations that reach its wrapper. The corrected distinction among
source submissions, receiver attempts, and accepted completions is in
[`ffg-receiver-acceptance-audit.md`](ffg-receiver-acceptance-audit.md).
