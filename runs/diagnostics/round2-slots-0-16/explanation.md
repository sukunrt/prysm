**Why the preflight failures prevent proposals.** The exact source gives each slot an absolute deadline of `genesis + (slot+1)*12s`. `runner.go` calls `RolesAt` synchronously and dispatches proposer work only afterward. `RolesAt` includes sync-committee selection. The fresh context created after role discovery uses the same absolute deadline; it does not renew the budget. Thus slots 2, 3, 4, 7, 11, and 12 have a source-backed dependency chain: synchronous preflight has not returned by the deadline → proposer starts with an expired deadline → RANDAO prerequisite fails → block RPC is not issued. The paired errors are not two independent failures.

The preflight start is absent from the historical logs. Proposer settings, attester aggregator selection, and other work precede the logged failing call. It is therefore incorrect to say that each individual sync RPC demonstrably occupied all twelve seconds. For the five sync-index cases, the server path includes a per-slot async lock and, on a cache miss, head-state access and slot processing. Slot 4 instead reaches the signing-domain path. The logs do not time these internal operations.

A different role's output proves role dispatch by `+9.915` (`validator.log:686`), but no markers record proposer-goroutine start, acquisition of the proposer-role lock, domain-cache lock acquisition, or DomainData handler admission. **Why packing errors have different meanings.** `buildBlockGloas` starts a consensus-field goroutine, obtains/selects a payload on the caller, then waits for the consensus goroutine before computing the block state root. If local payload and fallback both fail, it returns before the wait. This makes the late packing cancellations in slots 5, 6, 8, and 9 consequences of abandoned work, rather than the event that ended the request.

Slots 10 and 14 must join the consensus branch because payload selection succeeds. Their late packing-error logs show that the required branch had not finished on time. There is no wait-entry marker: the caller also records the selected bid under `lastBidLock` before joining, so the log does not establish its exact location at the deadline. The packing error itself is handled by putting empty deposits/attestations in the candidate; it is not directly propagated as the final build error. Once the branch finally returns, state-root processing sees cancellation and fails. The established chain is unfinished consensus work → deadline expires with a required result unavailable → late branch return → state-root cancellation/build failure.
