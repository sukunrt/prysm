01 / 08

Set the mission and the limits.

This guide gives you a safe build order. It also identifies the decisions that the source specifications do not make.

Keep

Goldfish selects the head.

Goldfish supplies the available-chain state, Ω. It selects one block from the set that the finality gadget permits.

Add

Fresh Simplex limits the set.

The gadget supplies the start block, the height filter, and the finalized block. It does not assign head weights.

Keep

Prysm imports blocks.

Keep the state transition, the data-availability barrier, the database writes, and the execution-engine call.

Defer

Do not build all variants.

Defer the inactivity leak, stability filter, and prefix counting. Do not defer sub-rounds: a sub-round is one slot, the round is 8 slots, and this 4× duty rate is the point of the simulation.

Language rule

This guide uses short commands and one meaning for each technical term. Code names, protocol names, and mathematical symbols are necessary technical terms. They are not STE dictionary words.

Update — an executable specification now exists

This workbook was written from the LaTeX papers. An executable profile now exists at ../decoupled-consensus-networking/consensus-specs/specs/_features/simplex/ and it decides everything on the wire. Three of its decisions change this workbook. One: a sub-round is one slot, so no second clock is necessary. Two: the syncer view-merge relay is out of scope. Three: the head gate is a previous-slot majority rule (is_available_attestation_viable). See decoupled-consensus-networking-mock.html for the current plan and the not-implemented list.

Important difference

A slot and a height are not the same unit. Goldfish makes one block in a slot. One gadget height can continue for many slots. A justification quorum or a timeout quorum advances the height by one.

03 / 08

Trace the current write paths.

A block and an attestation do not enter fork choice in the same way. Preserve this fact during the first implementation stage.

BLOCK PATH synchronous
GossipSub→block validator→handler→ReceiveBlock→InsertNode→Head

The block validator reads fork choice. The handler then calls ReceiveBlock. The function takes the fork-choice write lock at blockchain/receive_block.go:124. It keeps the lock until the function returns.

ATTESTATION PATH pool and timer
GossipSub→attestation validator→pool 1→timer A→pool 2→timer B→ProcessAttestation

The gossip handler only writes to pool 1. Timer A runs at 7.0, 9.5, and 11.8 seconds. Timer B runs at 0 and 10 seconds. The 10-second action runs only when the node has validators. Attestations in a block use a second path. handleBlockAttestations writes them without the pools and without the delay.

05 / 08

Implement the state machine in the specified order.

Branch order changes the result. Keep one function for each state change. Test each function without gossip or clocks.

Process one vote.

if vote.target == nil:
    if vote.height == state.h:
        state.timeouts[validator] = true
else:
    fresh = vote.height == state.h
        and strictAncestor(vote.target, state.L)
        and vote.target.slot >= state.sH
    if fresh:
        state.targets[validator] = vote.target
        state.timeouts[validator] = true

# Run this gate for every vote. Freshness does not control it.
if vote.finalizeHeight == state.hJ
   and vote.finalizeTarget == state.J:
    state.P.add(validator)

Process height events.

# 1. Finality falls through.
if size(state.P) >= quorum:
    state.F = state.J

# 2. Justification returns.
T = targetWithMostVotes(state.targets)
if T != nil and votesFor(T) >= quorum:
    state.J = T
    state.hJ = state.h
    state.P = empty
    advanceHeightAndResetVotes(state)
    return

# 3. A timeout does not change J, hJ, P, or F.
if timeoutCount(state.timeouts) >= quorum:
    advanceHeightAndResetVotes(state)
Three exact rules

Use a strict ancestor test for the vote target. Let the finality branch fall through. Clear P only after justification. A timeout must not clear P.

Update the node store.

onBlock(store, block):
    require block.parent in store.tree
    require ancestorOrSelf(store.F, block)
    state = stateTransition(store.state[block.parent], block)
    store.state[block] = state
    store.hMax = max(store.hMax, state.h)
    updateJustified(store, state.J, state.hJ)
    updateFinalized(store, state.F)

getConfirmed(store, omega):
    R = store.J if store.hMax == store.hJ + 1 else store.F
    candidates = viable descendants of R with height >= store.hMax - 1
    return omega.select(candidates)

07 / 08

Prove each boundary with an acceptance check.

Do not use only end-to-end tests. A fault in a timer can look like a fault in fork choice.

State-machine checks

  • A vote for the current head does not pass the strict-ancestor test.
  • A fresh justification vote sets both the target and the timeout marker.
  • A timeout quorum advances h by one and does not change J, hJ, P, or F.
  • A justification quorum has priority over a timeout quorum in the same call.
  • A finality quorum can finalize and advance the height in the same call.
  • An empty slot can process a height event before it increments s.

Store checks

  • hMax is the maximum height over all blocks in the tree, not only the leaves.
  • The justified update uses the key (hJ, hash(J)) after the finalized-ancestor filter.
  • The finalized update uses strict progress, ancestry to J, and viability.
  • The head search starts at J only when hMax == hJ + 1.
  • Goldfish selects a block only from the set that the gadget permits.

Integration checks

  • A gossip vote and an in-block vote use the same expiry rule.
  • A node without validators still processes received votes and updates its head.
  • An unknown block does not leave a vote in pool 2 without an expiry limit.
  • The execution engine gets the finalized hash from store.F.
  • The slot clock and the gadget clock cannot take locks in opposite orders.
  • A new gossip topic has a mapping, score, decoder, subnet rule, and topic declaration.
08 / 08

Record the open choices before code hides them.

The source specifications leave some items incomplete or inconsistent. Make each local choice visible.

VALIDATOR COUNT OR STAKE

The specification counts validators. Prysm counts effective balance. Select one quorum model and name it.

Rprime AT GENESIS

The healing text does not give an initial value. Use genesis for the first mock.

STABILITY CRITERION

The specification leaves the selection criterion abstract. Defer the filter or use the finality-vote target.

INACTIVITY LEAK

The sub-round repair has three options and no selected option. Do not add the leak to version one.

TIMEOUT-VOTE LIMIT

In the papers, a syncer can send a vote for each missing height. The syncer is out of scope, so this risk is dormant. Record it in case the syncer returns.

TWO DELTA MEANINGS

The text uses Δ(AC) for a slot duration and for a message-delay bound. Define two names before you set timers.

POOL 2 EXPIRY

The current fork-choice pool has no independent expiry. Add a slot limit before you use slot-scoped votes.

LOCK ORDER

The block path, attestation timer, and gadget timer can all write the store. Specify one lock order.

Ready criterion

The mock is ready for a devnet when four conditions hold. The pure tests pass. The parallel logs explain every difference. All pools have a limit. All three writers use the same lock rule.
