Prysm · Decoupled Consensus · Option A, mainnet build

Hardcode SLOTS_PER_EPOCH = 8 into the mainnet build

The quick experiment: mainnet-shaped everything, 8-slot epochs, one attestation stream at 4× today's rate. Three files change and one command regenerates the SSZ code. Tests are allowed to break. The binary must never touch a real network.

Why not the minimal preset

The minimal build already has 8-slot epochs, but it drags in 6-second slots, 4-member committees, a 32-member sync committee, a 16-member PTC, and 64-slot history vectors. The slot time and committee shape are runtime-overridable; the compiled sizes are not. For a mainnet-shaped measurement it is less work to move one number in the mainnet preset than to move a dozen numbers back in the minimal one. All line numbers from change rooyqxqp (Hegota registration).

00 The decision

This is a lab binary. Two costs are accepted up front.

  • Spec tests break. The mainnet spec-test vectors are generated for 32-slot epochs. make test mainnet-spectest will fail wholesale. Accepted.
  • The binary is network-poisonous. It keeps mainnet fork versions but changes the SSZ shape of the state. It must only ever run on a closed devnet with its own genesis. A devnet genesis has its own genesis validators root, so all fork digests differ from mainnet and real peers will refuse it — but do not rely on that; keep it off public bootnodes.
What this buys

One attestation per validator per 8 slots — the 4× finality-vote rate of decoupled consensus — on the real path: real 64-subnet spread, real aggregators, real block inclusion, real fork choice, 12-second slots, mainnet committee sizes. No new message type, no new topic, no Hegota logic needed. Gloas and Hegota stay at FarFutureEpoch for this experiment; run the chain at Fulu.

01 The three layers where 32 lives

The same number exists in three places that do not read each other. All three must agree, and only one of them is a yaml value.

Layer 3 has a single source of truth: the mainnet dictionary in proto/ssz_proto_library.bzl. make gen (build/gen/) reads that dictionary, substitutes the placeholders in the .proto files, and rewrites the checked-in .pb.go and .ssz.go files. The minimal twins (*.minimal.pb.go, *.minimal.ssz.go) come from the minimal dictionary and are not touched by this change.

Three files, one regeneration command. Every SLOTS_PER_EPOCH-derived size in the mainnet dictionary, and nothing else.

Do not touch the look-alikes

Several entries in the same dictionary contain 8192 or a power of two that smells like slots, but is not slots-per-epoch: block_roots.size and state_roots.size (SLOTS_PER_HISTORICAL_ROOT = 8192), slashings.size (EPOCHS_PER_SLASHINGS_VECTOR = 8192), randao_mixes.size (EPOCHS_PER_HISTORICAL_VECTOR = 65536), execution_payload_availability.size (SLOTS_PER_HISTORICAL_ROOT again), ptc.size / ptc_committee_indices.size (PTC_SIZE = 512, a committee size). Leave every one of them alone.

Four constants, same formulas as above. The file is guarded by //go:build !minimal; the minimal file stays untouched.

Edit 3 — config/params/mainnet_config.go:110–111

SlotsPerEpoch:        32 8
SqrRootSlotsPerEpoch: 5  2   // floor(sqrt(8)) — used in altair/attestation.go:305

Everything else in the runtime config stays at mainnet values: 12-second slots, 64 committees per slot, target committee size 128, aggregator target 16, EpochsPerEth1VotingPeriod = 64 (the voting period shortens from ~6.8 h to ~1.7 h of wall time — harmless on a devnet).

Edit 4 — regenerate

make gen proto ssz mode=force

This rewrites the mainnet .pb.go and .ssz.go files from the edited dictionary. Then go build ./... (no build tag — mainnet is the default).

Why this works when the yaml alone does not

The failure mode of the yaml-only approach was two halves of the code disagreeing: runtime duty logic computing 16 lookahead entries while the SSZ vector demanded 64. After these edits there is exactly one value of the number again, everywhere, at compile time. Internal consistency is the whole requirement — a closed devnet of identical binaries does not care that its state roots match no spec vector.

05 Run it

Genesis at Fulu, forks scheduled through epoch 0, Gloas and Hegota left in the far future. The 4× measurement needs no Hegota logic.

R1

Write the devnet yaml. Base it on mainnet values; the compiled defaults now already say 8, so the yaml only needs the fork ladder and network identity.

CONFIG_NAME: devnet-8slot · ALTAIR…FULU_FORK_EPOCH: 0 · GLOAS/HEGOTA: far future · MIN_GENESIS_ACTIVE_VALIDATOR_COUNT and GENESIS_DELAY to taste

R2

Generate the genesis state with the same binary. prysmctl testnet generate-genesis --fork fulu with the yaml and interop keys. Note --fork accepts only supported forks (cmd/prysmctl/testnet/generate_genesis.go:137 uses version.All(), which excludes Gloas and Hegota).

prysmctl testnet generate-genesis --fork=fulu --num-validators=N --chain-config-file=devnet.yaml --output-ssz=genesis.ssz

R3

Start beacon nodes + validators with the yaml and the genesis file, peered only with each other (--no-discovery --peer=… or a private bootnode).

beacon-chain --chain-config-file=devnet.yaml --genesis-state=genesis.ssz --interop-eth1data-votes …

R4

Confirm the shape before measuring: epochs tick every 96 s, and each slot carries ≈ n/8 single attestations instead of n/32.

subnet spread: committees per slot = clamp(n / 8 / 128, 1, 64) — all 64 subnets are busy only at n ≥ 65 536 validators

Committee spread caveat at small n

With 8-slot epochs and target committee size 128, a 10 000-validator devnet fills ~9 committees per slot, so ~9 of the 64 subnets carry traffic each slot. Today's mainnet at the same n would fill ~2. The per-subnet load ratio is still 4×, but absolute subnet coverage depends on validator count — record n with every run, as the mock plan already demands for the preset.

06 Verify

Cheap checks first. Each one catches a different class of mistake.

  • Build: go build ./... — catches a missed fieldparams constant or a generated-file drift.
  • Consistency: go test ./config/fieldparams/ — the common_test.go assertions are exactly the runtime-vs-compiled agreement this change must restore.
  • Generator canary: make test minimal-spectest (or any minimal-tag build) — proves make gen did not disturb the minimal twins.
  • State round-trip: go test ./beacon-chain/state/state-native/... — exercises marshal/unmarshal/HTR with the new vector sizes, including the proposer_lookahead padding at state_trie.go:722. Expect some literal-32 test failures; read them, don't chase them.
  • Live smoke: on the devnet, justification within 2 epochs (~3.2 min) and finalisation within 3. If the chain finalises, committee assignment, shuffling, and aggregation all agree about the number 8.
  • The measurement precondition: count beacon_attestation_* messages per slot on one node; it must be ≈ n/8. If it reads ≈ n/32, a 32 survived somewhere in the duty scheduler.

07 After this — what the hack cannot tell you

This binary answers the first question of the mock plan. Three limits remain, and they are the reason Option B follows.

  • One stream, not two. This is the finality stream at 4×. The Goldfish available_attestation topic — 512 messages per slot, flat in n, global mesh — is absent. Its load must be added before any capacity claim.
  • Wrong publish time. These attestations wait for the one-third-slot deadline. The real finality vote freezes its fields at round start and ships at the start of the slot, colliding with block propagation. That collision is unmeasurable here.
  • Epoch semantics moved. Shuffling period, aggregator count per slot, and finalisation cadence all changed with the epoch length. Fine for a first traffic number; label every result with this document.

When these numbers are in hand, proceed to Option B (steps B1–B8 of the mock plan): keep 32-slot epochs, add the cloned vote topics behind the registered Hegota fork, publish at slot start, and add the available_attestation topic.
