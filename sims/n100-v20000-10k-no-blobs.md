# 100-node comparison with small execution payloads and no blobs

2026-10-06. Requested follow-up to the 256 KiB runs: reduce execution-layer
traffic to examine whether Prysm's home-node FFG delay follows workload.
Both simulations completed successfully on ethp2p after launching in parallel.
Prysm took 1,374.15 seconds; eth-slot-sim took 647.76 seconds. All postprocessing
completed and the results were collected locally. Historical PIDs: driver
1033950; Prysm Shadow 1060549; eth-slot-sim Shadow 1060550.
The effective generated configuration was checked: one EOA spammer, no blob
spammer, 9,216-byte calldata, 10,240-byte eth-slot-sim payload, no-blob mode,
unchanged 8/128 column subscriptions, all 99 configured peers, eight groups of
2,500 FFG voters, PTC at 6s and FFG aggregates at 9s.

## Workload

| Setting | Prysm | eth-slot-sim |
|---|---|---|
| Execution payload | Approximately 10 KiB, measured after inclusion | 10,240 bytes |
| Transaction injection | Spamoor EOA, one transaction per 12-second slot | No separate EL transaction model |
| Calldata | 9,216 random bytes per EOA transaction | Included in modeled payload bytes |
| EOA pending / wallet limits | 4 / 32 | Not applicable |
| Blob workload | Disabled | No blob column publication |
| Block gas limit | 200,000,000 | No EVM execution model |

One 9 KiB calldata transaction plus transaction encoding and execution payload
overhead should produce roughly 10 KiB. The post-run audit records every slot's
actual payload bytes, transaction count and blob count. Startup wallet funding,
inclusion timing and withdrawals can cause variation; slot 1 starts empty.
The EOA transaction gas allowance remains 1,150,000; it is independent of the
200-million block gas limit. The old Spamoor seed and wallet count are retained.

The blob spammer is generated and its wallets premined to preserve the genesis
and host layout, then its process is removed from the effective Shadow YAML
before launch. No blob scenario runs. The generated `sim.yaml` alone therefore
does not represent the effective blob workload; use `data/shadow.yaml` and the
run manifest.

## Retained configuration

Both simulators use 100 nodes, 20,000 validators, 80 home and 20 super nodes,
16 measured slots, one FFG subnet and 2,500 voters per slot. The eight staggered
validator groups repeat twice. Individual FFG votes publish at slot start,
without the Prysm delay/spread flag or configured jitter. ePBS stays enabled,
FFG aggregates publish at 9s and the PTC deadline is 6s. The earlier distinction
between Prysm's early PTC sending and eth-slot-sim's deadline sending remains.

Placement, geography, link capacities, peer identities and 99-peer connectivity
targets are retained. All 128 data-column subnet assignments remain configured:
eight subscriptions per home and 128 per super. Peer scoring and mesh rules are
unchanged. Prysm uses the same binaries as the 256 KiB 16-slot baseline.

## Run-specific eth-slot-sim adjustment

The baseline binary hardcodes six blobs in `validator/column.go`; setting
`data_columns.blobs: 0` alone does not remove its column burst. A Go build overlay
adds an explicit `run.no_blob_data` experiment setting. With that setting,
ePBS publishes no column messages and the slot has no required blob custody;
PTC still requires receipt of the payload and publishes at the configured 6s.
Column subscriptions stay intact. This does not modify the shared eth-slot-sim
checkout or its existing binaries. The earlier peer-connectivity audit overlay
is retained. Overlay sources, binary hashes and validation commands are saved
with the run.

The focused no-blob test checks absent column publications/receipts, complete
PTC delivery at exactly 6s, and a negative PTC result when a receiver misses the
payload. Existing driver/schedule tests and vet passed before launch (driver
tests: 42.780s). The binary was built with an isolated source copy plus overlays.

## Interpretation and analysis

Compare FFG average, median, p95 and p99 by home/super receiver class and across
all slots, alongside receipt completeness. Report final-slot Prysm 16 versus
eth-slot-sim 15 separately, plus the corresponding 256 KiB baseline.

This changes transaction load, execution payload size and blob availability
together. Removing blob transactions also removes CL data-column sidecars, so
an improvement supports a workload/queueing explanation but does not isolate
EL dissemination from CL column load or prove that peer scoring has no effect.
The existing transport, publication-offset and measurement-stage differences
also remain.

## Completed results

Final slot: **Prysm 16 / eth-slot-sim 15**. All times below are milliseconds
from slot start and exclude publisher receipts. Both final FFG ledgers contain
247,500 unique remote receipts.

| FFG receiver | Average | Median | p95 | p99 |
|---|---:|---:|---:|---:|
| Prysm home | 378 | 249 | 1,253 | 1,966 |
| Prysm super | 111 | 98 | 224 | 289 |
| eth-slot-sim home | 375 | 277 | 989 | 1,484 |
| eth-slot-sim super | 351 | 312 | 835 | 1,321 |

Overall FFG average / median / p95 / p99: **327 / 203 / 1,140 / 1,880ms**
for Prysm and **371 / 284 / 967 / 1,419ms** for eth-slot-sim.

The final Prysm execution payload is **10,299 bytes**, compared with eth-slot-sim
at **10,240 bytes**: a difference of 59 bytes (0.58%). Prysm slots 3–16 stay at
10,298–10,299 bytes. The final payload contains one transaction, zero blobs,
and uses 610,824 gas with a 200,000,000 block gas limit. The final beacon block
contains one FFG aggregate and one payload attestation. Both simulators record
zero column sidecars, as intended.

All **16 slots in both simulators have complete individual FFG receipt
ledgers**, with 2,500 publishers and 247,500 distinct remote receipts per slot.
The baseline had 2,663 missing Prysm records across six slots; its final slot
was complete. Current FFG publications remain at 0–6ms for Prysm and within
1.26ms for eth-slot-sim. Runtime identity audits confirm all 99 peers per node
at the captured boundaries, including 1,700 eth-slot-sim audits. All final-slot
validation checks pass; there are no parser failures or final-slot errors.

### Effect relative to the 256 KiB 16-slot baseline

| Final FFG receiver | Baseline avg / p95 / p99 | Small-payload avg / p95 / p99 |
|---|---:|---:|
| Prysm home | 530 / 1,565 / 2,947 | 378 / 1,253 / 1,966 |
| Prysm super | 124 / 269 / 369 | 111 / 224 / 289 |
| eth-slot-sim home | 408 / 1,161 / 1,807 | 375 / 989 / 1,484 |
| eth-slot-sim super | 292 / 541 / 732 | 351 / 835 / 1,321 |

Prysm home average improves 28.6%, p95 19.9% and p99 33.3% in the final slot.
Its home average now closely matches eth-slot-sim, while home p95 remains
26.7% higher. Across all slots, Prysm home p99 stays between 1,918 and 2,301ms,
compared with 2,415–9,147ms in the heavier run (some baseline ledgers were
incomplete). No progressively worsening home tail appears in this run.

The result supports workload contributing to the earlier long delays and
missing records. It does not isolate EL gossip from CL columns, since both
loads changed. It also does not establish peer scoring as the cause of the
remaining class split. These are individual runs: eth-slot-sim super latency
increases despite lower traffic, demonstrating that the observed differences
cannot all be attributed to a simple bandwidth reduction. Mesh histories or
repeated/scoring-controlled runs are still needed for that causal claim.
