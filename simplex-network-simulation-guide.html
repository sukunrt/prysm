THE RESULT TO PRODUCE

For each node count and fault profile, report the minimum network budget that delivers each required message phase to the target fraction of nodes.

This result does not prove safety, liveness, or finality. It shows the network capacity envelope.
01 / 06

Test transport, not consensus.

Keep the parts that can change message propagation. Replace the parts that only decide a chain head or a finality state.

Use real code

Prysm P2P service

Use libp2p, GossipSub meshes, topic scoring, SSZ with Snappy, validation queues, peer discovery, and subscriber loops.

Use real schedule

Message deadlines

Publish messages at the Simplex boundaries. The round-start TSQ relay burst is out of scope: see the traffic-class table.

Use real objects

Wire types

Construct valid finality attestations, available attestations, aggregates, and blocks. Send their exact SSZ and Snappy representation.

Replace after validation

Fork-choice result

Return deterministic roots after the real decoder, structural checks, committee checks, and signature verification complete.

Measure

Cryptographic cost

Create real signatures and run real individual, aggregate, and fast-aggregate verification. Include these times in the primary result.

Do not claim

Protocol correctness

Do not infer consensus correctness from delivery. Report only timing, coverage, load, loss, and recovery.

Recommended test boundary

Port the actual Simplex wire types and gossip validators into Prysm. Supply cached fixture states, committees, keys, and a small block-root graph to those validators. After a message passes the real checks, record it and stop before the consensus state transition.

The simulation target is 8 slots per round. Each validator then has one finality duty per 8 slots, which is 4 times the one-per-32-slots attestation rate of an epoch. The available-vote transport budget is 3 seconds on a 12-second slot. Record the slot time and the round length in the run metadata.

Round-start load shape

Do not test only a steady message rate. The round-start block carries the whole round's finality aggregates, and a block holds at most 8 attestation entries — one round exactly, with no headroom. Measure round-start block arrival separately from ordinary slots. The larger TSQ relay burst is out of scope.

Convert measurements into a finality-time envelope.

Select a coverage target and a tail percentile before the run. Do not select them after you see the result.

tᵢ(C*) = earliest time at which message phase i reaches coverage C*
B_pipeline = construct + sign + encode + publish + propagate + decode + verify
B_required = Σ tᵢ(C*) for sequential message phases
B_required = max tᵢ(C*) for parallel message phases
target is supported when B_required + scheduled waits ≤ T_target

Use end-to-end pipeline time for the primary verdict. Also report each stage separately so that you can identify a network, serialization, or cryptographic bottleneck. For the available-vote path, the block pipeline must fit the first 25% and the available-attestation pipeline must fit the next 25%.

What it means to add AvailableAttestation

Use one production object

The Simplex gossip object is AvailableAttestation. It is already an aggregate. Do not add an AvailableAttestationMessage, a validator-index wrapper, or a test envelope. A validator contribution sets all committee positions that belong to that validator and signs AvailableAttestationData one time.

// proto/prysm/v1alpha1/simplex.proto
message AvailableAttestationData {
  uint64 slot = 1;                 // cast to primitives.Slot
  bool payload_present = 2;
  bytes beacon_block_root = 3;     // ssz-size: 32
}

message AvailableAttestation {
  bytes aggregation_bits = 1;      // Bitvector[512]: 64 SSZ bytes
  AvailableAttestationData data = 2;
  bytes signature = 3;             // ssz-size: 96

Available-attestation gossip order

  1. IGNORE an object from a future slot or from a slot other than the current slot.
  2. IGNORE an object when its block root is not known. Put it in the bounded dependency queue.
  3. REJECT an object when the block is known but its validation or cached state failed. Reject an object from the wrong fork.
  4. REJECT an object when the voted block slot is later than the attestation slot. Reject payload_present=true when both slots are equal.
  5. IGNORE an older-block vote with payload_present=true until the payload is verified.
  6. IGNORE an object when the finalized checkpoint is not an ancestor of the voted block.
  7. Get the target checkpoint state. REJECT an object whose bitvector is not 512 bits, whose selected committee set is empty, or whose selected positions are invalid.
  8. Resolve the selected positions to validator identities. Deduplicate the identities. REJECT the object when fast-aggregate BLS verification fails.
  9. Apply the data-root, bit-superset, and equivocation indexes. IGNORE an object that supplies no new signer evidence and does not extend known bits.
  10. Call OnAvailableAttestation. For this network test, the facade stores the accepted evidence that later network validation needs and returns a deterministic result. It does not select a head or finalize a block. Return ACCEPT only after this call succeeds.

Port the actual gossip validators.

Port the validation sequence from specs/_features/simplex/p2p-interface.md. Keep each check in its specified ACCEPT, IGNORE, or REJECT class.

  1. For a single finality attestation: check slot and round freshness. Check the 128-slot latest-message window. Check the voted-head dependency and target-chain compatibility. Check committee membership, the subnet, and the individual BLS signature.
  2. For an aggregate: require one committee and valid aggregation bits. Require a selected aggregator with a valid selection proof. Require a valid aggregator signature and a valid aggregate attestation signature.
  3. For an available attestation: require the current slot and a known valid block root. Require correct payload status and finalized ancestry. Require a 512-position bitvector and valid committee positions. Verify one fast-aggregate signature over distinct validator identities.
  4. For a block: use a cached parent state. Check time, parent presence, and slot order. Check finalized ancestry, the proposer index, the payload relation, operation limits, and the proposer signature. Permit one distinct second round-start block, as the specification requires.
  5. Replace the old epoch-keyed seen rules with round-keyed rules. Forward the first valid attestation and one distinct conflicting copy. Ignore further copies from that signer and round.
  6. Put messages with unknown named blocks in a bounded dependency queue. Retry them when the block or ancestry arrives. Do not build the TSQ relay pool of concrete signed messages: it is out of scope.
  7. Call the networking-state handler before forwarding where the Simplex P2P text requires it. The handler can update seen and dependency data, but it must not run the finality state transition.

Pre-run checklist

  • Every node records the same out-of-band run ID, parameter hash, and simulation-clock origin.
  • The mesh is warm before measured traffic starts.
  • The colocation whitelist contains all simulator address ranges.
  • File-descriptor, port, memory, and connection limits are above the planned load.
  • All primary runs construct and verify real BLS signatures.
  • The SSZ objects contain no simulation-only field or padding field.
  • The dependency store and event sink have explicit size limits.
  • No high-cardinality identifier is a Prometheus label.
  • Each configuration runs multiple times with different topology and duty seeds.
  • The final report says “network capacity,” not “consensus correctness.”
